3. eCommerce Asset Diagnosis — Technical & Content Audit

Keyword matrix, technical health, on-page quality, schema, off-page authority, and GEO visibility.

3A. Technical Health

🔴

Critical: Duplicate <title> and <meta description> tags (all pages)

Every crawled page (homepage, /roof-systems, /products, /blog) injects two separate <title> tags and two <meta name="description"> tags. Google will arbitrarily pick one — or use neither, substituting its own snippet. This actively suppresses CTR by making meta previews unpredictable. Root cause: a global site-wide tag in the template <head> plus a page-specific tag added via a plugin/component. Fix: audit the theme's <head> template and ensure only one canonical meta block fires per page.

🔴

Critical: Duplicate og:title, og:description, og:url Open Graph tags (all pages)

Two competing sets of OG tags are rendered on every page (one global set + one page-specific set). When this page is shared on social media or parsed by AI crawlers, the first or random set gets used — often the less optimized global default. Fix: same root cause as duplicate <title> — consolidate to one OG block per page.

🔴

Critical: Google Index Coverage Is Extremely Thin

A site: search returns only 5 indexed URLs for theroofstore.net despite the sitemap containing 100+ pages. This strongly suggests either a crawl budget issue, the service-area/city pages being seen as thin/duplicate content by Google, or the sitemap only recently being submitted. Immediate action: verify Google Search Console index coverage report, check for manual actions, ensure the 80+ city pages have unique content of at least 300–400 words each.

🟡

Warning: FAQ Page Has No Indexable Answer Text

The /faq page renders only question titles — all answers appear to be hidden behind collapsible elements (likely JS accordion). Google may not execute the JS, meaning the FAQ content is invisible to crawlers. This page could be a goldmine for FAQ schema and featured snippets ("Can I coat my roof instead of replacing it?" — exactly what people search). Fix: include answer text in the HTML source, not just on expand.

🟡

Warning: robots.txt Blocks Nothing — Verify No Sensitive Pages Are Exposed

robots.txt is wide open: User-agent: * Allow: /. While this is generally fine, the /shop, /privacy, /terms, and any admin/internal pages should be verified as non-sensitive. Additionally, there is no separate Disallow for cart, checkout, or duplicate-parameter URLs.

🟡

Warning: www vs non-www — Canonical Ambiguity

The sitemap and og:url use both https://www.theroofstore.net and https://theroofstore.net (without www). The blog posts link to theroofstore.net (no www). The canonical tags use the www version. Ensure a 301 redirect from non-www to www (or vice versa) is fully enforced, and that all internal links, canonical tags, og:url, and sitemap entries are consistent.

✅

Positive: robots.txt declares sitemap correctly

Sitemap URL is declared in robots.txt at https://www.theroofstore.net/sitemap.xml. Sitemap is well-structured with proper changefreq and priority values. Updated timestamps are current (July 2026).

✅

Positive: Canonical tags present and correctly self-referential

Every crawled page includes a proper self-referencing canonical URL. No apparent canonical mismatches on the pages sampled.

5. Plugin / Performance Debt

Script load, rendering, and CMS configuration issues that affect Core Web Vitals and SEO.

🔴

Dual Metadata Injection — Root Cause: Template Conflict

The site injects two complete sets of <title>, <meta description>, og:*, and twitter:* tags per page. This is the classic pattern of a CMS theme that adds a global metadata block in the <head> template AND a per-page SEO plugin (or React/Next.js head component) that adds a second set. Identify which system owns meta tag generation and disable the duplicate. This is the highest-priority fix on the site.

🟡

Blog Running on Separate "Just another WordPress site" Instance

The blog's browser title renders as "Just another WordPress site — The Roof Store." This is the WordPress default tagline — it was never customized. This tells Google (and users) that the blog is a low-effort subdirectory. It also means the WordPress blog settings (tagline, site title) have never been configured, which suggests the SEO plugin configuration on the WordPress blog instance may be incomplete.

🟡

JavaScript-Hidden FAQ Content (Accordion Pattern)

The FAQ's question answers are rendered only when JavaScript expands the accordion. Googlebot may not render this JS. This is both a technical SEO issue (content not indexed) and a schema opportunity (FAQPage schema requires visible Q&A pairs). Fix: render answer text in HTML and use JS only to visually collapse/expand, or SSR the FAQ content.

✅

Semantic HTML Structure is Well-Implemented

All sampled pages include <header>, <nav>, <main>, <section>, and <footer> semantic tags. This is good for accessibility and crawlability. Heading hierarchy (H1 → H2 → H3) is mostly logical, though H4/H5 usage is absent where it could subdivide longer sections.
